**HikrobotScanner** — это настольное приложение WPF (.NET), предназначенное для управления сканером (камерой) Hikrobot ID5000. Приложение запускает TCP-сервер для приема данных от сканера, обрабатывает полученные коды и сохраняет валидные результаты в файловой системе.

## 🚀 Основные возможности

- **Управление камерой:** Подключение к сканеру Hikrobot по IP-адресу (либо к единственной найденной камере).
- **Загрузка профиля:** Возможность выбора и загрузки пользовательских настроек (UserSet) для камеры при инициализации.
- **TCP-сервер:** Запуск TCP-слушателя для приема данных (результатов сканирования) от камеры на указанном порту.
- **Обработка данных:**
  - Немедленная обработка входящих данных от сканера.
  - Валидация данных: поиск одного уникального 20-значного линейного штрих-кода.
  - Валидация QR-кодов: проверка на соответствие ожидаемому количеству (6 или 8).
- **Сохранение данных:** Сохранение валидных и уникальных (по линейному коду) данных в файл сессии в папку `codes`.
- **Генерация штрих-кодов:** Встроенный инструмент для генерации и печати линейных штрих-кодов (CODE-128) с использованием счетчика, который сохраняется между запусками.

- **Логирование:** Ведение лога событий в реальном времени, отображаемого в интерфейсе.

## ⚙️ Технологический стек
- **.NET 9** (`net9.0-windows`)
- **WPF (Windows Presentation Foundation)** - для пользовательского интерфейса.
- **MVVM (Model-View-ViewModel):** Архитектурный паттерн, реализованный с помощью `CommunityToolkit.Mvvm`.
- **Dependency Injection:** Управление зависимостями через `Microsoft.Extensions.DependencyInjection`.
- **ZXing.Net:** Библиотека для генерации штрих-кодов.
- **MvCameraControl.Net.dll:** Официальная библиотека (SDK) от Hikrobot для управления камерами.

## 🔧 Как это работает

1. **Настройка:** Пользователь вводит IP-адрес камеры, порт для прослушивания и выбирает профиль настроек (UserSet) в главном окне.

2. **Запуск сервера:** При нажатии "Старт сервера":
   - Приложение подключается к камере по указанному IP через SDK Hikrobot (или к единственной обнаруженной камере) и загружает выбранный профиль.
   - Запускается TCP-сервер, который начинает прослушивать указанный порт.

3. **Получение данных:**
   - Камера сканирует и отправляет результат (например, `QR1#QR2#...#LinearCode`) на указанный порт.

4. **Обработка:**
   - `MainViewModel` сразу обрабатывает полученную строку.
   - Система выделяет линейный штрих-код (20 цифр) и QR-коды.
   - Проводится валидация: линейный код должен быть один, а количество уникальных QR-кодов должно быть не меньше настройки (6 или 8).

5. **Сохранение:**
   - Если данные валидны и такой линейный код еще не был обработан, полная строка (`ЛинейныйКод#QR1#...#QR_N`) сохраняется в файл текущей сессии в папке `codes`.

## ⚙️ Конфигурация
Все основные параметры настраиваются через пользовательский интерфейс и сохраняются в `App.config` (через `Properties.Settings`):
- **IP камеры:** IP-адрес сканера.
- **Локальный порт (прием):** Порт, на котором приложение будет ожидать данные от камеры.
- **Ожидаемое кол-во QR кодов:** (6 или 8) - используется для валидации.
- **Профиль настроек камеры:** (UserSet1, UserSet2, UserSet3) - профиль, загружаемый в камеру при запуске.
